# DB-002 — Organizations Data Dictionary**Document ID:** DB-002**Version:** 1.0**Status:** Approved**Owner:** Atlas Engineering**Depends On:** DB-001 – Atlas Domain Model---# PurposeThis document defines the `organizations` entity for Atlas.The Organization is the root entity in the Atlas multi-tenant architecture. Every business object in the system belongs to exactly one organization.No operational data may exist without an owning organization.---# Business DefinitionAn Organization represents a restoration company that subscribes to and operates within the Atlas platform.Examples include:- Roofing contractors- Water damage restoration companies- Fire restoration contractors- General restoration businesses- Multi-branch restoration enterprises---# Table Nameorganizations---# Primary Key| Column | Type | Required | Description ||---------|------|----------|-------------|| id | UUID | Yes | Unique identifier for the organization. documents- photos- workflows- tasks- ai_sessions- ai_conversations- ai_recommendations- supplements- compliance_reviews- reports- notifications- integrations- audit_logs- voice_sessionsAll child tables must include an indexed `organization_id` foreign key.---# Business Rules1. Every business record belongs to exactly one organization.2. Organizations are archived rather than permanently deleted.3. Organization data must never be visible across tenants.4. The `slug` must be globally unique.5. Feature flags determine module availability without requiring code changes.6. Changes to organization settings must be recorded in the audit log.---# Validation Rules- `legal_name` cannot be empty.- `display_name` cannot be empty.- `slug` must contain only URL-safe characters.- `email` must be a valid email address.- `session_timeout_minutes` must be greater than zero.- Retention periods cannot be negative.---# Recommended Indexes| Column | Index Type ||---------|------------|| slug | Unique || legal_name | B-tree || subscription_status | B-tree || country | B-tree || created_at | B-tree || archived_at | B-tree |---# Future EnhancementsThe Organizations domain may later support:- Multi-brand organizations- Branch offices- Regional divisions- Multiple business units- Per-branch feature configuration- White-label deploymentsThese capabilities should be implemented through related tables rather than by overloading the `organizations` table.---# Acceptance CriteriaThe Organizations data model is complete when:- All required business information can be stored.- Tenant isolation is enforced.- Feature configuration is supported.- Security and retention policies are configurable.- Audit fields are standardized.- Child entities can safely reference the organization.---# Next Document**DB-003 — Organizations Entity Relationship Diagram (ERD)**This document will define every relationship from the `organizations` table to the rest of the Atlas platform and will serve as the blueprint for the PostgreSQL schema and ORM models.
