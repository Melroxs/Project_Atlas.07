# Database Architecture OverviewVersion: 1.0Status: ApprovedOwner: Atlas EngineeringLast Updated: July 2026---# PurposeThis document defines the database architecture for Atlas.Atlas uses PostgreSQL as the primary transactional database with Supabase providing managed infrastructure, authentication, storage, realtime capabilities, Row Level Security (RLS), and edge functions.The database is designed for:- Enterprise scalability- Multi-tenancy- AI-native workflows- Evidence-driven reasoning- Auditability- High availability- Security by default---# Core Principles## Single Source of TruthEvery business object has exactly one authoritative record.Examples:ClaimsSupplementsDocumentsEvidenceDecisionsCustomersOrganizations---## AI-Native DesignThe database is designed for AI first—not AI added later.Examples include:Conversation historyMemoryEmbeddingsEvidence relationshipsConfidence scoringDecision reasoningKnowledge Graph---## Immutable Audit HistoryNo important business action is ever lost.Instead of deleting:Version recordsSoft deleteEvent sourcingAudit logsDecision history---## Event DrivenChanges create events.Examples:Claim CreatedDocument UploadedSupplement GeneratedDecision ApprovedEvidence AddedVoice Session Completed---## Domain DrivenThe schema is organized into logical business domains rather than technical layers.---# Logical Domains## PlatformAPI KeysWebhooksBackground JobsFeature FlagsIntegrationsAnalytics---# Database TechnologyPrimary DatabasePostgreSQL 17+Managed LockingSoft DeletesVersion History---# Multi-Tenant ModelTenant = OrganizationEvery business record belongs to exactly one organization.Example:Organization↓Claims↓Supplements↓Evidence↓Documents↓AI DecisionsCross-tenant access is never permitted.---# Security ModelAuthenticationSupabase (future)Connection poolingZero downtime migrations---# ScalabilityExpected ScaleOrganizations100,000+Users2M+Claims500M+Documents5B+Embeddings10B+Architecture supports horizontal application scaling while maintaining a single authoritative PostgreSQL cluster.---# Design GoalsThe Atlas database must:Remain highly normalizedSupport AI reasoningSupport vector searchProvide complete auditabilityScale globallyRemain cloud portableSupport enterprise complianceEnable future analytics and machine learning workloads
