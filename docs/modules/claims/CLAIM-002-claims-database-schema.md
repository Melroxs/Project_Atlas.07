# CLAIM-002 — Atlas Claims Database Schema**Document ID:** CLAIM-002**Version:** 1.0**Status:** Draft**Owner:** Atlas Engineering**Depends On:**- CLAIM-001 Claims Management Architecture- USER-002 Users & Teams Database Schema- PLAT-003 Multi-Tenant Architecture- PLAT-005 Audit Logging Framework---# PurposeThis document defines the database schema for the Atlas Claims Management module.The schema supports:- Insurance claims.- Customer records.- Properties.- Claim assignments.- Status tracking.- Activity history.- AI integration.---# Database Design PrinciplesClaims follow these rules:- Every claim belongs to one organization.- Every claim belongs to one customer.- Every claim belongs to one property.- Every status change is recorded.- Every important action is auditable.- Historical records are preserved.---# Entity Relationship Overview```Organization      |   Claims      | ------------------------------------------------ Customer Property Assignments Status History Activities ------------------------------------------------```---# Table 1 — customers## PurposeStores restoration customers.A customer may have multiple claims.---## Schema```customersidorganization_idfirst_namelast_nameemailphonecreated_atupdated_atdeleted_at```---# Fields| Field | Type | Description ||-|-|-|| id | UUID | Customer identifier || organization_id | UUID | Tenant owner || first_name | VARCHAR | First name || last_name | VARCHAR | Last name || email | VARCHAR | Email address || phone | VARCHAR | Contact number || created_at | TIMESTAMP | Created date || updated_at | TIMESTAMP | Updated date || deleted_at | TIMESTAMP | Soft deletion |---# IndexesRequired:```customers_organization_idxcustomers_email_idx```---# Table 2 — properties## PurposeStores physical locations connected to claims.---## Schema```propertiesidorganization_idcustomer_idaddress_line_1address_line_2citystatepostal_codecountryproperty_typecreated_atupdated_at```---# Property TypesExamples:```RESIDENTIALCOMMERCIALMULTI_UNITOTHER```---# Table 3 — claims## PurposePrimary operational record.---## Schema```claimsidorganization_idcustomer_idproperty_idclaim_numberstatusloss_typeloss_datecause_of_lossinsurance_companypolicy_numbercarrier_claim_numberadjuster_nameadjuster_emailadjuster_phoneassigned_user_iddescriptionestimated_valuecreated_atupdated_atdeleted_at```---# Claim Status Enum```NEWINTAKEDOCUMENT_COLLECTIONASSESSMENTESTIMATE_CREATEDSUPPLEMENT_REVIEWAPPROVEDPRODUCTIONCOMPLETEDCLOSED```---# Loss Type EnumExamples:```WATERFIRESTORMROOFMOLDOTHER```---# Claim IndexesRequired:```claims_organization_idxclaims_status_idxclaims_number_idxclaims_customer_idxclaims_assigned_user_idx```---# Table 4 — claim_assignments## PurposeTracks users responsible for claims.---## Schema```claim_assignmentsidorganization_idclaim_iduser_idassignment_typecreated_at```---# Assignment Types```PRIMARY_OWNERESTIMATORPROJECT_MANAGERSUPPLEMENT_SPECIALISTCOLLABORATOR```---# Table 5 — claim_status_history## PurposeCreates a historical record of claim movement.---## Schema```claim_status_historyidorganization_idclaim_idprevious_statusnew_statuschanged_byreasoncreated_at```---# Example```Claim:12345Previous:ASSESSMENTNew:SUPPLEMENT_REVIEWChanged By:MelissaReason:Missing scope identified```---# Table 6 — claim_activities## PurposeStores timeline events.---## Schema```claim_activitiesidorganization_idclaim_idactivity_typetitledescriptioncreated_bymetadata JSONBcreated_at```---# Activity TypesExamples:```CLAIM_CREATEDDOCUMENT_UPLOADEDPHOTO_ADDEDNOTE_CREATEDAI_ANALYSIS_COMPLETEDSUPPLEMENT_GENERATEDTASK_CREATED```---# JSON MetadataExample:```json{ "documentId":"abc123", "confidence":0.91}```---# Claim Number GenerationEach organization maintains its own numbering.Example:```ATLAS-2026-00001ATLAS-2026-00002```---# Tenant IsolationEvery table includes:```organization_id```Every query must include:```WHERE organization_id = currentOrganization```---# Foreign KeysRequired relationships:```claims.customer_id→ customers.idclaims.property_id→ properties.idclaim_assignments.claim_id→ claims.idclaim_assignments.user_id→ users.idclaim_status_history.claim_id→ claims.idclaim_activities.claim_id→ claims.id```---# Claim Deletion StrategyClaims should not be permanently deleted.Use:```deleted_at```for soft deletion.Reason:Insurance records require historical traceability.---# AI RequirementsClaims must support AI processing.Future relationships:```claims↓documents↓evidence↓ai_analysis↓recommendations```---# Audit EventsRequired:```claim.createdclaim.updatedclaim.status.changedclaim.assignedclaim.closed```---# Migration OrderDatabase creation order:```1. customers2. properties3. claims4. claim_assignments5. claim_status_history6. claim_activities```---# Acceptance CriteriaClaims database is complete when:- Claims can be stored.- Customers are linked.- Properties are linked.- Assignments work.- Status history is preserved.- Timeline events are recorded.- Tenant isolation exists.- AI systems can access claim context.---# Next
