# KNOWLEDGE_GRAPH_SCHEMA.md## PurposeThe Atlas Knowledge Graph Schema defines the canonical data model for representing knowledge across the platform. It establishes the node types, relationships, ontology, validation rules, indexing strategy, and governance model that allow Atlas to reason over claims, projects, evidence, documents, photos, communications, and organizational knowledge.This schema serves as the foundation for the Evidence Graph, Atlas Memory Engine, Decision & Confidence Engine, and all future AI capabilities.---# Design GoalsThe schema must:* Represent all restoration knowledge consistently.* Support explainable AI reasoning.* Enable semantic and graph-based search.* Maintain complete auditability.* Scale to millions of interconnected entities.* Remain extensible as new intelligence modules are introduced.---# Core Principles* Every entity is a node.* Every connection is an explicit relationship.* Every relationship has meaning.* Every fact has provenance.* Every AI conclusion is traceable.* Every schema change is versioned.* Organization data is strictly isolated.---# Graph ArchitectureThe Atlas Knowledge Graph consists of:* Nodes* Relationships (Edges)* Properties* Labels* Ontology* Constraints* Indexes* Embeddings* Metadata* Version History---# Primary Node Categories## ClaimRepresents an insurance claim.Properties:* Claim ID* Claim Number* Policy Number* Carrier* Status* Date of Loss* Cause of Loss* Created Date* Updated Date---## ProjectRepresents a restoration project linked to one or more claims.Properties:* Project ID* Name* Status* Start Date* Completion Date* Assigned Team---## PropertyRepresents the physical location.Properties:* Property ID* Address* Building Type* Year Built* Square Footage* Occupancy Type---## RoomRepresents an interior or exterior area.Examples:KitchenBathroomGarageRoofAtticExteriorBasementLaundryProperties:* Room ID* Room Type* Floor* Area* Description---## PersonExamples:CustomerEstimatorProject ManagerTechnicianAdjusterReviewerAdministratorProperties:* Person ID* Name* Role* Organization* Contact Details---## CompanyExamples:Insurance CarrierContractorVendorEngineering FirmMitigation CompanyProperties:* Company ID* Name* Type* Region---## PhotoRepresents uploaded imagery.Properties:* Photo ID* File Reference* Capture Time* GPS Metadata* Photographer* Analysis Status---## DocumentExamples:EstimateInvoiceInspection ReportContractPolicyLetterEmailProperties:* Document ID* Type* Version* Source* Status---## SupplementProperties:* Supplement ID* Status* Submitted Date* Approved Date* Estimated Value* Approved Value---## Estimate Line ItemProperties:* Item ID* Description* Quantity* Unit* Price* Trade---## Damage ObservationProperties:* Observation ID* Damage Type* Severity* Confidence* Source---## MaterialExamples:DrywallInsulationTileCarpetHardwoodRoofingPaintTrimProperties:* Material ID* Category* Manufacturer (optional)* Notes---## InspectionProperties:* Inspection ID* Inspector* Inspection Date* Summary* Status---## CommunicationExamples:Phone CallEmailSMSMeetingChatProperties:* Communication ID* Type* Timestamp* Participants* Transcript Reference---## MemoryRepresents institutional knowledge captured by Atlas.Properties:* Memory ID* Summary* Confidence* Source* Version---## DecisionRepresents an AI or human decision.Properties:* Decision ID* Recommendation* Confidence* Risk* Status---# Relationship TypesExamples include:CLAIM_HAS_PROJECTPROJECT_LOCATED_ATPROJECT_HAS_ROOMROOM_CONTAINS_DAMAGEPHOTO_SHOWS_DAMAGEPHOTO_TAKEN_IN_ROOMPHOTO_SUPPORTS_SUPPLEMENTDOCUMENT_SUPPORTS_LINE_ITEMDOCUMENT_REFERENCES_CLAIMSUPPLEMENT_REQUESTS_LINE_ITEMLINE_ITEM_REPAIRS_DAMAGEINSPECTION_IDENTIFIED_DAMAGECOMMUNICATION_REFERENCES_CLAIMPERSON_CREATED_DOCUMENTPERSON_APPROVED_SUPPLEMENTCOMPANY_EMPLOYS_PERSONMEMORY_REFERENCES_PROJECTDECISION_SUPPORTED_BY_EVIDENCEDECISION_REQUIRES_REVIEW---# Relationship PropertiesEvery relationship stores:* Relationship ID* Source* Target* Confidence* Created Date* Updated Date* AI Model Version* Human Verified* Evidence References---# Ontology RulesEvery node belongs to one or more categories.Every relationship must:* Have a defined type.* Connect valid node types.* Include provenance.* Be timestamped.* Support auditing.---# Validation RulesReject:* Orphan nodes* Invalid relationship types* Circular ownership references* Missing required identifiers* Invalid tenant referencesWarn:* Duplicate entities* Weak evidence* Low-confidence links* Missing metadata---# Identity ResolutionAtlas should detect when multiple records represent the same entity.Examples:Duplicate customer recordsDuplicate vendor recordsDuplicate property addressesDuplicate project referencesIdentity resolution should require human review when confidence is below configurable thresholds.---# Graph VersioningEvery schema version records:* Version Number* Release Date* Migration Notes* Breaking Changes* CompatibilityHistorical versions remain available for audit purposes.---# ProvenanceEvery fact must record:* Source* Collection Method* Timestamp* User or System* Evidence Reference* ConfidenceNo fact should exist without provenance.---# Indexing StrategyIndexes should be created for:Claim NumberProject IDProperty IDDocument IDPhoto IDSupplement IDPerson IDCompany IDMemory IDDecision IDRelationship TypeTimestampSemantic Embeddings---# Semantic LayerEach searchable object receives:* Embedding Vector* Keywords* Summary* Entity Labels* Context ReferencesSupports:* Semantic Search* Similarity Search* Context Retrieval* AI Reasoning---# Graph QueriesSupported query patterns include:Find all evidence supporting a supplement.Locate every photo of kitchen water damage.Show claims with similar roof damage.Identify projects involving the same property.List communications mentioning mold.Display all decisions linked to this estimate.---# Knowledge IngestionKnowledge enters the graph from:Photo IntelligenceDocument IntelligenceOCRVoice TranscriptsManual EntryWorkflow EventsExternal IntegrationsAtlas MemoryDecision EngineSupplement Intelligence---# GovernanceSchema changes require:Architecture reviewMigration planBackward compatibility assessmentDocumentation updateVersion increment---# SecurityRequirements include:Role-based access controlTenant isolationEncryption at restEncryption in transitImmutable audit historyLeast-privilege access---# Audit ModelRecord:Who created dataWho modified dataWhen changes occurredPrevious valuesCurrent valuesReason for changeAssociated workflow---# Performance TargetsNode creation:<100 millisecondsRelationship creation:<100 millisecondsGraph traversal:<500 millisecondsSemantic search:<2 secondsContext assembly:<2 seconds---# Integration PointsThe schema supports:Evidence GraphAtlas Memory EngineDecision & Confidence EnginePhoto IntelligenceDocument IntelligenceSupplement IntelligenceVoice OrchestrationWorkflow EngineAnalytics PlatformCompliance EngineExternal APIs---# MVP ScopeIncluded:* Canonical ontology* Core node types* Standard relationship model* Provenance tracking* Validation rules* Identity canonical language of the Atlas platform. It provides a unified, explainable, and extensible representation of restoration knowledge, enabling every AI capability—from evidence analysis and supplement generation to organizational memory and voice orchestration—to reason over the same trusted foundation. By connecting people, projects, evidence, documents, and decisions through a governed knowledge graph, Atlas establishes the technical backbone for an AI-native operating system for restoration companies.
