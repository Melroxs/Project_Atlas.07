# ATLAS_MEMORY_ENGINE_SPEC.md## PurposeThe Atlas Memory Engine is the persistent organizational intelligence layer of the Atlas platform. It captures, organizes, retrieves, and continuously refines knowledge generated across every claim, project, customer interaction, and business process.Unlike conversational memory, the Atlas Memory Engine is designed to preserve institutional knowledge so that every completed project improves future decision-making.---# VisionAtlas should remember:* How your company performs work* Which supplement strategies succeed* Which documentation carriers typically request* Preferred estimating practices* Company SOPs* Lessons learned from completed claims* Historical project outcomes* Team preferences and workflowsEvery interaction should make Atlas more knowledgeable.---# ObjectivesThe Memory Engine will:* Preserve organizational knowledge* Learn from completed projects* Improve future recommendations* Support semantic search* Personalize AI responses* Reduce repeated work* Capture institutional expertise* Provide contextual reasoning---# Guiding Principles* Organization-owned knowledge* Explainable retrieval* Human verification* Continuous learning* Secure tenant isolation* Version-controlled memory* Evidence-backed knowledge---# Memory Categories## Organizational MemoryStores:* SOPs* Estimating standards* Approval workflows* Business rules* Templates* Internal policies---## Project MemoryStores:* Completed projects* Project outcomes* Timelines* Lessons learned* Revenue recovered* Common issues---## Claim MemoryStores:* Claim history* Adjustments* Supplements* Evidence packages* Communications* Final outcomes---## Customer MemoryStores:* Property history* Previous claims* Communication preferences* Historical work performed* Project notes---## Carrier MemoryStores configurable organizational observations such as:* Documentation preferences* Submission formats* Common information requests* Review timelines* Frequently requested clarifications---## Team MemoryStores:* Estimator preferences* Reviewer notes* Approval history* Internal best practices* Reusable knowledge---## Technical MemoryStores:* Building materials* Repair methods* Equipment usage* Industry terminology* Code references* Internal documentation---# Memory SourcesKnowledge is created from:* Photos* Documents* OCR* Voice transcripts* Emails* Estimates* Supplements* Inspections* Timeline events* Human annotations* Workflow decisions* Evidence Graph---# Memory LifecycleKnowledge progresses frequencyRecency scoreOverall confidenceConfidence Levels:Very HighHighModerateLowArchived---# Learning ProcessAtlas learns from:Completed claimsApproved supplementsRejected supplementsReviewer feedbackOutcome comparisonsProject retrospectivesOperational metricsUser corrections---# Semantic RetrievalUsers should be able to ask:How do we normally document mold claims?Have we repaired this property before?Show similar roof claims.What usually gets rejected by this carrier?Find projects involving hardwood flooring.What supplements have the highest approval rate?---# Context AssemblyBefore answering, Atlas assembles context from:Evidence GraphCurrent claimRelevant memoriesHistorical outcomesOrganizational proceduresActive documentsApplicable compliance rules---# PersonalizationResponses may adapt based on role:EstimatorProject ManagerReviewerAdministratorTechnicianExecutiveEach receives context appropriate to their responsibilities.---# Memory RankingRetrieval should consider:Semantic similarityEvidence strengthRecencyUsage frequencyHuman verificationProject similarityConfidence---# Memory ConsolidationDuplicate knowledge should be merged.Examples:Repeated SOPsDuplicate observationsEquivalent repair proceduresIdentical lessons learnedMerged memories retain:Version historyOriginal sourcesEvidence linksAudit history---# Memory ExpirationCertain memories should be reviewed over time:Carrier guidanceInternal proceduresPricing assumptionsOperational processesExpired memories are never deleted automatically; they are archived pending review.---# Human ReviewUsers may:Approve memoryReject memoryEdit summaryMerge memoriesSplit memoriesArchive memoryRestore archived memoryEvery action is audited.---# Memory It transforms every completed claim, project, document, conversation, and decision into reusable institutional knowledge. By preserving experience, linking it to evidence, and making it instantly retrievable, Atlas enables restoration companies to continuously improve their operations and ensure that valuable expertise is never lost.
