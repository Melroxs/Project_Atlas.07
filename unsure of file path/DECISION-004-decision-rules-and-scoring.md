# DECISION-004 — Atlas Decision Rules & Scoring Engine**Document ID:** DECISION-004**Version:** 1.0**Status:** Draft**Owner:** Atlas Engineering---# PurposeThis document defines the reasoning rules and scoring framework used by the Atlas Decision Engine.The Decision Engine evaluates:- Evidence strength.- Missing information.- Compliance requirements.- Revenue impact.- Risk factors.to generate explainable recommendations.---# Core Decision PrincipleAtlas does not make decisions from AI confidence alone.A decision requires:```Evidence Quality+Evidence Coverage+Rule Validation+Risk Assessment```---# Decision Pipeline```Claim Context      ↓Evidence Evaluation      ↓Rule Matching      ↓Score Calculation      ↓Risk Assessment      ↓Recommendation      ↓Human Review```---# Scoring FrameworkEvery decision receives three primary scores.---# 1. Evidence Confidence ScoreMeasures:```How reliable is the supporting evidence?```Range:```0.00 - 1.00```---## Evidence Confidence Factors| Factor | Weight ||---|---:|| Source reliability | 30% || Evidence completeness | 25% || Evidence consistency | 25% || AI confidence | 20% |---## ExampleEvidence:```Inspection Report+Photos+Estimate Comparison```Result:```Evidence Score:0.89```---# 2. Decision Confidence ScoreMeasures:```How likely the recommendation is correct.```Formula:```Decision Confidence =Evidence Score+Rule Match Score+Compliance Alignment-Contradictions```---# 3. Risk ScoreMeasures:```Potential negative impact.```Range:```0 - 100```---# Risk Factors## Missing EvidenceExample:```Required photo missing```Impact:```+20 risk```---## Conflicting EvidenceExample:```Estimate differs from inspection```Impact:```+30 risk```---## Compliance GapExample:```Required documentation missing```Impact:```+40 risk```---# Supplement Opportunity Rules## Rule SUP-001### Missing Scope DetectionTrigger:```Evidence indicates damageANDEstimate does not contain related item```Example:```Photo:Damaged flashingEstimate:Roof replacement only```Result:```Supplement OpportunityConfidence calculatedHuman approval required```---# Rule SUP-002## Evidence RequirementA supplement recommendation requires:Minimum:```2 supporting evidence sources```Examples:Accepted:```Photo+Inspection Report```or:```Document+Estimate Comparison```---# Rule SUP-003## Confidence ThresholdSupplement recommendations:```Confidence >= 0.70```Allowed:```Generate recommendation```Below:```Request more evidence```---# Compliance Rules## Rule CMP-001Missing required documentation.Example:Required:```Moisture Documentation```Available:```None```Result:```Compliance Warning```---## Rule CMP-002Evidence verification.Requirement:```Recommendation must have traceable sources```Failure:```Decision blocked```---# Claim Review Rules## Rule REV-001Conflicting EvidenceTrigger:```Two sources disagree```Example:```Estimate:Minor damagePhotos:Major damage```Result:```Claim Review Required```---# Priority CalculationPriority determines urgency.Formula:```Priority =Revenue Impact+Risk Level+Deadline Sensitivity```---## Priority Levels### LOWExample:```Additional documentation suggestion```---### MEDIUMExample:```Missing evidence```---### HIGHExample:```Potential revenue leakage```---### CRITICALExample:```Compliance failure before submission```---# Human Approval RulesThe following always require human approval:```Financial recommendationsClaim changesSupplement submissionsExternal communication```---# Decision Confidence Matrix| Confidence | Action ||-|-|| 0.90 - 1.00 | Strong recommendation || 0.70 - 0.89 | Recommendation with review || 0.50 - 0.69 | Request more evidence || Below 0.50 | No recommendation |---# Revenue Recovery LogicAtlas identifies:```Potential Scope-Included Scope=Possible Recovery Opportunity```Example:```Observed damage:Roof flashingEstimate:MissingAtlas:Potential supplement opportunity```---# Explainability OutputEvery decision generates:```Recommendation:Why:Evidence:Confidence:Risk:Next Action:```Example:```Recommendation:Review roof flashing supplementWhy:3 photos show damageInspection confirms affected areaEstimate excludes flashingConfidence:91%Risk:LowNext Action:Human review```---# Decision Engine Safety RulesAtlas must never:❌ Automatically submit supplements❌ Modify claim values❌ Communicate with carriers without approval❌ Create unsupported recommendations---# Acceptance CriteriaDecision Rules are complete when:✅ Evidence scoring exists✅ Confidence scoring exists✅ Risk scoring exists✅ Supplement rules exist✅ Compliance rules exist✅ Human approval rules exist✅ Explanations are generated---# Next Document## DECISION-005 — Decision Repository LayerThis implements storage operations for:- Creating decisions.- Saving scores.- Linking
