# EVIDENCE-001 — Atlas Evidence Graph Architecture**Document ID:** EVIDENCE-001**Version:** 1.0**Status:** Draft**Owner:** Atlas Engineering---# PurposeThis document defines the architecture for the Atlas Evidence Graph.The Evidence Graph transforms disconnected information into connected business intelligence.---# Business ProblemRestoration companies currently have:- Photos in folders.- Estimates in PDFs.- Adjuster notes in emails.- Policies in documents.- Measurements in reports.The information exists, but relationships are invisible.Example:A photo showing water damage may support:```Drywall Replacement+Flooring Removal+Mold Remediation```But traditional systems do not connect these relationships.---# Core PrincipleAtlas does not understand files.Atlas understands relationships.---# Evidence Graph ConceptAn Evidence Graph is a network of:```Nodes+Relationships+Confidence Scores+Context```---# High-Level Architecture```                 Claim                  |        ---------------------        |          |        |    Documents   Photos   Estimates        |          |        |        ---------------------                  |            Evidence Graph                  |        ---------------------        |                   | Compliance Engine     Decision Engine        | Supplement Engine```---# Evidence Graph Components## 1. NodesNodes represent objects Atlas understands.Examples:```ClaimDocumentPhotoEstimate Line ItemPolicy RequirementDamage AreaMaterialRecommendation```---# Node Types## Claim NodeRepresents:```Insurance Claim```Contains:- Claim information.- Customer.- Property.- Carrier.---## Document NodeExamples:```Estimate.pdfPolicy.pdfInspection Report```---## Photo NodeRepresents:```Damage Evidence```Contains:- Timestamp.- Location.- Description.- AI analysis.---## Estimate Line Item NodeExamples:```Drywall RepairRoof ReplacementWater Extraction```---## Compliance Rule NodeRepresents:```Required evidenceRequired documentationIndustry rules```---## Recommendation NodeRepresents:```AI Suggested Action```Examples:```Request additional photosReview missing scopeVerify coverage```---# RelationshipsRelationships describe how evidence connects.---# Relationship Types## SUPPORTSExample:```PhotosupportsRoof Replacement```---## CONTRADICTSExample:```Estimate says:Minor DamagePhoto shows:Major Damage```---## REQUIRESExample:```Policy RequirementrequiresInspection Report```---## DERIVED_FROMExample:```Recommendationderived fromEvidence Set```---# Evidence Confidence ModelEvery relationship receives:```Confidence Score0 - 1```Example:```Photo supports roof replacementConfidence:0.92```---# Evidence ObjectConceptual model:```Evidence {idtypesourceclaimIdconfidencerelationshipsmetadata}```---# Evidence Graph ExampleScenario:Storm claim.Atlas discovers:```Claim↓Storm Damage↓Inspection Report↓Roof Damage Photos↓Estimate Missing:Roof Flashing↓Recommendation:Review Supplement Opportunity```---# Evidence Reasoning Pipeline```Collect Evidence        ↓Normalize Information        ↓Create Relationships        ↓Calculate Confidence        ↓Identify Gaps        ↓Generate Recommendations```---# Supplement IntelligenceThe Evidence Graph enables:## Missing Scope DetectionExample:Estimate:```Roof replacement```Evidence:```Damaged flashingDamaged ventsWater intrusion```Atlas:```Potential missing scope detected```---# Compliance IntelligenceExample:Requirement:```Water loss requires moisture documentation```Evidence:```No moisture map found```Atlas:```Compliance gap identified```---# Voice Assistant IntegrationThe business becomes queryable.Example:User:> "Atlas, why are we recommending this supplement?"Atlas:Response:```Recommendation based on:3 damage photosInspection reportEstimate comparisonConfidence: 89%Human approval required.```---# Decision Engine IntegrationEvidence Graph feeds:```Claim↓Evidence↓Rules↓Decision Engine↓Recommendation```---# Security RequirementsEvidence must respect:- Organization isolation.- Claim permissions.- Audit logging.- Source traceability.Every recommendation must answer:```Where did this come from?Why does Atlas believe this?Who approved it?```---# Future EnhancementsPlanned:- Computer vision damage detection.- Carrier-specific reasoning.- Historical claim learning.- Automatic evidence scoring.- Real-time claim monitoring.---# Acceptance CriteriaEvidence Graph is complete when:✅ Claims become connected objects✅ Documents become evidence sources✅ Photos become evidence nodes✅ Relationships can be created✅ Confidence scores exist✅ Recommendations have explanations✅ AI responses are traceable---# Next DocumentsEVIDENCE-002 — Evidence Graph Database SchemaEVIDENCE-003 — Evidence Domain TypesEVIDENCE-004 —
