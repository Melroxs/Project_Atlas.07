# Database Naming ConventionsVersion: 1.0---# GoalsMaintain consistency.Improve readability.Reduce ambiguity.Support automated code generation.---# TablesPlural snake_case.Examples:usersorganizationsclaimssupplementsdocumentsvoice_sessionsknowledge_nodes---# Columnssnake_case.Examples:created_atupdated_atorganization_idclaim_numberconfidence_scorereasoning_summary---# Primary KeysAlways:id UUIDExample:id UUID PRIMARY KEY---# Foreign KeysFormat:<entity>_idExamples:claim_idorganization_iduser_idphoto_iddocument_id---# Junction TablesAlphabetical naming.Examples:claim_documentsevidence_photosknowledge_evidenceuser_roles---# Boolean FieldsPrefix with:is_has_can_Examples:is_deletedhas_evidencecan_edit---# Timestamp FieldsRequired:created_atupdated_atOptional:deleted_atapproved_atcompleted_atprocessed_atexpires_at---# Enum NamingSuffix:_type_statusExamples:claim_statusdocument_typedecision_statussupplement_status---# Index NamingFormat:idx_<table>_<columns>Examples:idx_claims_statusidx_documents_claimidx_line_items_code---# Unique Constraintsuq_<table>_<column>Example:uq_users_email---# Foreign Key Constraintsfk_<table>_<reference>Example:fk_claims_customer---# Check Constraintschk_<table>_<rule>Example:chk_confidence_score---# Trigger Namingtrg_<table>_<action>Examples:trg_claims_updated_attrg_documents_version---# FunctionsVerb first.Examples:calculate_confidence()generate_embeddings()link_evidence()refresh_memory()---# ViewsPrefix:vw_Examples:vw_claim_summaryvw_open_supplementsvw_ai_metrics---# Materialized ViewsPrefix:mv_Examples:mv_daily_metricsmv_claim_statistics---# Storage BucketsLowercase.Plural.Examples:documentsphotosexportsavatarsvoicetraining-data---# General RulesNo abbreviations unless universally accepted.Use UUIDs instead of integer IDs.Avoid reserved SQL keywords.Prefer descriptive names over short names.Use UTC timestamps throughout.Never overload column meanings.Maintain backward compatibility wherever possible.
