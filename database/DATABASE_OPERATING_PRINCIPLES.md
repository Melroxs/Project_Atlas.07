# Database Operating Principles1. PostgreSQL is the authoritative source for transactional data.2. Every tenant-owned table enforces Row-Level Security.3. Object storage is used only for binary assets; metadata remains relational.4. Business records are soft deleted unless regulatory requirements dictate otherwise.5. All schema changes are implemented through version-controlled migrations.6. Every production database change is reviewed, tested, and reversible where practical.7. Operational monitoring is mandatory for performance, availability, and security.8. Backup and recovery procedures are tested regularly.9. Auditability, explainability, and reproducibility are first-class design goals.10. Performance optimizations must never compromise data integrity or tenant isolation.11. Atlas is designed for horizontal application scaling while maintaining a single authoritative transactional database.12. Database architecture must remain cloud-portable and avoid unnecessary vendor lock-in.
