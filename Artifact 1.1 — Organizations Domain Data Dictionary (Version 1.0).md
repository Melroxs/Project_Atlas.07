Artifact 1.1 — Organizations Domain Data Dictionary (Version 1.0)PurposeThe Organization entity represents a restoration company using Atlas.Every other business entity (claims, customers, documents, users, photos, AI conversations, reports, etc.) belongs to an organization. This is the root of Atlas's multi-tenant architecture.Table: organizationsDescriptionStores information about each customer organization using Atlas.Primary records exist.Organizations may be archived instead of deleted.The slug must be unique across all organizations.Subscription status controls access to licensed features.Organization administrators cannot access data from other organizations.AI, Voice, Mobile, and API capabilities can be enabled or disabled independently.Required EnumsThe following enumerations will be defined in the (unique)emailsubscription_statuscreated_atcountrylegal_nameAcceptance CriteriaThe Organizations domain is complete when:Organizations can be created, updated, archived, and viewed.Tenant isolation is enforced for all related records.Organization-level settings control platform behavior.Branding and regional preferences are available throughout the application.Subscription and feature settings influence access without code changes.Next ArtifactThe next engineering artifact will be Artifact 1.2 – Organizations Entity Relationship Diagram (ERD).That ERD will define
