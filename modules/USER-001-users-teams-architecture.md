# USER-001 — Atlas Users & Teams Architecture**Document ID:** USER-001**Version:** 1.0**Status:** Draft**Owner:** Atlas Engineering**Depends On:**- PLAT-001 Authentication Architecture- PLAT-002 Authorization & RBAC- PLAT-003 Multi-Tenant Architecture- PLAT-005 Audit Logging Framework---# PurposeThis document defines the architecture for users, teams, and workforce management inside Atlas.Atlas is designed for restoration companies with multiple operational roles.Examples:- Owners.- Office administrators.- Estimators.- Project managers.- Technicians.- Supplement specialists.- Adjuster coordinators.---# User ModelA user represents an individual person who accesses Atlas.Relationship:```Organization      |    Users      |    Roles      | Permissions```---# User ResponsibilitiesUsers can:- Access company information.- Manage assigned workflows.- Interact with Atlas AI.- Use voice commands.- Perform authorized actions.---# User EntityCore fields:```UseridorganizationIdfirstNamelastNameemailphoneavatarUrlrolestatuscreatedAtupdatedAt```---# User StatusUsers have lifecycle states:```INVITED↓ACTIVE↓SUSPENDED↓DEACTIVATED```---# User TypesAtlas supports different workforce categories.---# Internal UsersEmployees of the restoration company.Examples:- Owner.- Operations manager.- Estimator.- Technician.---# External UsersFuture support:- Insurance adjusters.- Consultants.- Partners.External users have restricted permissions.---# Team ArchitectureTeams organize users operationally.Example:```Organization|Teams|Users```---# Example Teams## Estimating TeamMembers:- Estimators.- Supplement specialists.Responsibilities:- Estimates.- Supplements.- Evidence review.---## Production TeamMembers:- Project managers.- Technicians.Responsibilities:- Job execution.- Photos.- Updates.---## Administration TeamMembers:- Owners.- Office managers.Responsibilities:- Billing.- Reporting.- User management.---# Team EntityFields:```TeamidorganizationIdnamedescriptioncreatedAtupdatedAt```---# User-Team RelationshipA user may belong to multiple teams.Example:```John Smith|Estimating Team+Production Team```---# Invitation SystemNew users join through invitations.Flow:```Admin Creates Invitation        |Email Sent        |User Accepts        |Account Created        |Role Assigned```---# Invitation States```PENDING↓ACCEPTED↓EXPIRED↓CANCELLED```---# User PreferencesAtlas stores user preferences.Examples:- Dashboard layout.- Notification preferences.- AI interaction preferences.- Voice settings.---# AI PersonalizationAtlas can adapt to users.Examples:Estimator:"Show supplement opportunities."Project Manager:"Show delayed projects."Owner:"Show revenue recovery."---# Voice ContextEvery voice interaction resolves:```Voice↓User↓Role↓Organization↓Allowed Actions```Example:Technician:"Atlas, upload these photos."Allowed.Technician:"Atlas, approve this supplement."Denied.---# User SecurityUsers support:- MFA.- Session management.- Password policies.- Login history.---# User Audit EventsRequired:```user.createduser.inviteduser.updateduser.role.changeduser.suspendeduser.deleted```---# Database RequirementsRequired tables:```usersteamsteam_membersuser_invitationsuser_preferences```---# API RequirementsRequired operations:```createUser()inviteUser()acceptInvitation()updateUser()assignRole()removeUser()listUsers()getUserProfile()```---# AI RequirementsThe AI layer must know:```Current User+Organization+Role+Permissions```before answering queries or performing actions.---# Future EnhancementsPlanned:- Employee performance analytics.- Skills tracking.- Technician scheduling.- Workforce optimization.- Voice profiles.- AI coaching.---# Acceptance CriteriaUsers and Teams are complete when:- Users can join organizations.- Roles are assigned.- Teams organize operations.- Permissions are enforced.- AI understands user context.- Voice actions respect identity.- All actions are audited.---# Next DocumentsThe
