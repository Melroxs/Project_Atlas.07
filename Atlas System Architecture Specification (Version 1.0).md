Atlas System Architecture Specification (Version 1.0)1. Project OverviewProduct NameAtlasVisionAtlas is an AI-powered operating system for insurance restoration contractors. Its purpose is to make restoration companies "legible" to AI by centralizing operational data, documents, communications, and claim information into a single platform that assists teams in recovering revenue through compliant, evidence-backed insurance supplements.Problem StatementInsurance restoration companies lose significant revenue because:Documentation is incomplete or scattered.Evidence is difficult to locate.Supplement requests are inconsistent.Teams rely on manual processes.Knowledge is siloed across employees and software.Atlas addresses these issues by organizing company data, analyzing claims with AI, and generating structured recommendations supported by documentation and compliance checks.MVP GoalThe MVP should enable a restoration company to:Manage claims.Upload and organize claim documents.Store and review damage photos.Generate AI-assisted supplement recommendations.Validate recommendations against defined business and compliance rules.Produce a professional supplement package ready for human review.2. Target UsersPrimary UsersRestoration company ownersProject managersEstimatorsSupplement specialistsSecondary UsersOffice administratorsOperations managersSales managersExternal StakeholdersInsurance adjustersProperty owners (future phase)Third-party reviewers (future phase)3. Core ModulesThe initial Atlas MVP will consist of:Authentication & User ManagementOrganization ManagementDashboardClaims ManagementDocument ManagementPhoto ManagementAI Interview SystemAI Decision EngineSupplement ManagementCompliance ValidationReportingNotificationsActivity TimelineAdministrationEach module should be independently testable and documented.4. Architectural PrinciplesAtlas should follow these principles throughout development:Single responsibility: each module has one clear purpose.Modular design: components can evolve independently.Strong typing: TypeScript types are used throughout.API-first: frontend communicates only through defined APIs.Validation-first: all input is validated before processing.Security by default: authentication and authorization are enforced consistently.Human oversight: AI provides recommendations; final decisions remain with users.7. Initial Development StandardsUse TypeScript for all application code.Maintain a consistent folder structure.Keep business logic separate from UI components.Define database changes through migrations.Use reusable components where possible.Document all public APIs.Write tests alongside new functionality where practical.8. MVP Success CriteriaThe first production-ready version of Atlas should allow a user to:Sign in securely.Create and manage claims.Upload and organize documents and photos.Associate evidence with claims.Generate AI-assisted supplement recommendations.Review confidence scores and compliance checks.Produce a structured supplement package for human approval.Next DocumentWith this foundation established, the next specification should be Repository Structure & Development Environment. From there, we'll proceed into the database design and then the implementation of each application module.
