# DECISION-001 — Atlas Decision Engine Architecture**Document ID:** DECISION-001**Version:** 1.0**Status:** Draft**Owner:** Atlas Engineering---# PurposeThis document defines the architecture of the Atlas Decision Engine.The Decision Engine transforms:- Claim information.- Evidence relationships.- Compliance requirements.- Historical patterns.into:- Recommendations.- Risk assessments.- Required actions.- Revenue recovery opportunities.---# Core PrincipleAtlas does not replace human judgment.Atlas provides:```Evidence+Reasoning+Recommendation+Confidence```A human makes the final decision.---# Business ProblemRestoration companies lose revenue because:- Scope gaps are discovered too late.- Documentation is incomplete.- Evidence is disconnected.- Adjuster communication lacks support.- Compliance requirements are missed.The Decision Engine identifies these opportunities earlier.---# Decision Engine Architecture```                 Claim Data                     |             Evidence Graph                     |          Compliance Intelligence                     |            Decision Engine                     |      ---------------------------      |            |            | Recommendations  Risk       Actions                     |             Human Review```---# Decision PipelineAtlas follows a seven-stage reasoning pipeline:```1. Claim Intake        ↓2. Evidence Collection        ↓3. Evidence Evaluation        ↓4. Compliance Validation        ↓5. Decision Scoring        ↓6. Recommendation Generation        ↓7. Human Approval```---# Stage 1 — Claim IntakeInput:```ClaimPropertyInsurance CarrierLoss TypeDocuments```Example:```Water Damage ClaimCarrier:ABC InsuranceLoss Date:2026-07-01Property:Residential Home```---# Stage 2 — Evidence CollectionAtlas gathers:```DocumentsPhotosEstimatesInspection ReportsPolicy InformationCommunication History```The Evidence Graph provides relationships.---# Stage 3 — Evidence EvaluationAtlas evaluates:## Evidence QualityQuestions:```Is the source reliable?Is the evidence recent?Does it support the claim?Is confidence high enough?```---# Stage 4 — Compliance ValidationAtlas checks:```Required documentationRequired evidenceMissing informationPotential risks```Example:```Water mitigation claimRequires:✓ Moisture documentation✓ Photos✓ Timeline```---# Stage 5 — Decision ScoringEvery decision receives:## Confidence ScoreMeasures:```How likely is this recommendation correct?```Range:```0 - 100%```---## Risk ScoreMeasures:```Potential negative impact```Examples:```Missing documentationCompliance issueRevenue leakage```---# Decision Score ModelConceptual:```Decision Score =Evidence Confidence+Evidence Coverage+Compliance Alignment-Risk Factors```---# Stage 6 — Recommendation GenerationAtlas creates:```RecommendationReasonSupporting EvidenceConfidenceRequired Action```Example:```Recommendation:Review roof flashing supplementReason:Photos indicate damageInspection supports replacementEstimate does not include flashingConfidence:91%Action:Submit for human approval```---# Stage 7 — Human ApprovalAll financial-impacting decisions require review.Flow:```AI Recommendation        ↓Human Review        ↓Approve / Reject        ↓Audit Record```---# Decision TypesAtlas supports:## Supplement OpportunityExample:```Missing scope identified```---## Compliance WarningExample:```Required documentation missing```---## Claim ReviewExample:```Conflicting evidence detected```---## Document RequestExample:```Additional photos required```---# Decision ObjectConceptual model:```Decision {idclaimIdtyperecommendationevidenceSourcesconfidenceScoreriskScorestatuscreatedAt}```---# Explainability RequirementEvery decision must answer:## What?```What does Atlas recommend?```## Why?```What evidence supports this?```## Confidence?```How certain is Atlas?```## Action?```What should happen next?```---# Voice Assistant IntegrationExample:User:> "Atlas, what should I do with this claim?"Atlas:```This claim has a potential supplement opportunity.Reason:3 photos show additional damage.The estimate does not include related repairs.Confidence:88%Recommended action:Review supplement package.```---# Revenue Recovery IntelligenceThe Decision Engine focuses on:```Identifying missed scope+Supporting documentation+Reducing claim leakage```Example:Before Atlas:```Missed line items discovered weeks later```After Atlas:```Potential gaps identified during review```---# Security RequirementsDecision Engine must enforce:- Organization isolation.- User permissions.- Audit logging.- Evidence traceability.No decision can exist without:```Claim+Evidence+Explanation```---# Future EnhancementsPlanned:- Carrier-specific decision models.- Historical claim learning.- Predictive supplement probability.- Automated package preparation.- Multi-agent reasoning.---# Acceptance CriteriaDecision Engine Architecture is complete when:✅ Decisions have defined inputs✅ Evidence is connected✅ Confidence scoring exists✅ Risk scoring exists✅ Human approval exists✅ Explanations are generated✅ Auditability is maintained---# Next DocumentsDECISION-002 — Decision Engine Database
