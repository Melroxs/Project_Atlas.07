Atlas Claims Management Module Specification (Version 1.0)1. PurposeThe Claims Management module is the operational heart of Atlas. It provides a single workspace where all information related to an insurance restoration claim is managed, tracked, analyzed, and prepared for supplement generation.Each claim serves as the primary container for customer information, property details, documents, photos, AI analysis, compliance checks, tasks, communications, and supplements.2. ObjectivesThe module must enable users to:Create and manage claims.Track claim progress through standardized stages.Associate customers, properties, adjusters, and insurance carriers.Upload and organize supporting evidence.Record notes and tasks.Generate AI-assisted recommendations.Validate recommendations against compliance rules.Produce complete supplement packages for review.3. Core Claim LifecycleEvery claim progresses through defined stages.Proposed MVP WorkflowNew Claim    ↓Information Gathering    ↓Document Collection    ↓Photo Collection    ↓AI Analysis    ↓Supplement Draft    ↓Compliance Review    ↓Manager Review    ↓Submitted to Carrier    ↓Carrier Response    ↓Approved / Partially Approved / Denied    ↓ClosedEach transition should be validated to ensure required information has been collected before advancing.4. Claim RecordEach claim includes:IdentificationClaim IDClaim NumberPolicy NumberOrganizationCreated DateLast UpdatedCustomerProperty OwnerContact DetailsPropertyAddressLocationProperty TypeInsuranceInsurance CarrierAdjusterPolicy InformationAssignmentProject ManagerSupplement SpecialistCurrent Owner5. Claim Status RulesStatuses should include:DraftNewActiveAwaiting DocumentsAwaiting PhotosAI ProcessingSupplement DraftCompliance ReviewManager ReviewSubmittedCarrier Response PendingApprovedPartially ApprovedDeniedClosedArchivedEvery status change should be recorded in the activity timeline.6. Claim WorkspaceThe claim page should present all related information in one place.OverviewClaim summaryCurrent statusAssigned team membersKey datesCustomerContact informationCommunication history (future)PropertyAddressDamage overviewDocumentsUploaded filesOCR statusMissing documentsPhotosGalleriesDamage categoriesAI annotationsAIInterview resultsRecommendationsConfidence scoresSupplementsDraftsSubmitted versionsCarrier outcomesComplianceValidation resultsOutstanding issuesActivity TimelineChronological history of eventsNotesInternal commentsDecisionsTasksOutstanding workAssigned usersDue dates7. Required Claim InformationA claim cannot progress beyond early stages unless key information is present.Required data includes:CustomerPropertyInsurance carrierClaim numberLoss dateAssigned ownerAdditional requirements are enforced before later stages, such as document upload before AI analysis.8. Assignment WorkflowClaims can be assigned to:Project ManagerSupplement SpecialistOperations ManagerAssignment actions include:AssignReassignRemove assignmentView assignment historyAssignments should generate activity log entries and optional notifications.9. NotesUsers should be able to create internal notes.Each note includes:AuthorTimestampContentOptional categoryOptional attachment referenceNotes are internal and not included in exported supplement packages.10. TasksTasks help coordinate work on a claim.Fields include:TitleDescriptionAssigned userDue datePriorityStatusTasks may be created manually or automatically by workflow rules.11. Activity TimelineEvery significant event should appear in a chronological timeline.Examples:Claim created.Status changed.Document uploaded.Photo uploaded.AI analysis completed.Supplement generated.Compliance review completed.Package submitted.Carrier response recorded.This timeline provides a complete operational history.12. Search & FilteringUsers should be able to search and filter claims by:Claim numberCustomer nameProperty addressInsurance carrierAdjusterAssigned userStatusDate rangeSaved filters may be introduced in future releases.13. AI IntegrationThe Claims module orchestrates AI workflows.Possible actions include:Analyze claim completeness.Identify missing evidence.Suggest additional documentation.Recommend supplement opportunities.Summarize claim history.AI outputs should always reference supporting evidence and display confidence levels.14. Compliance IntegrationCompliance checks should verify:Required documents present.Required photos available.Evidence linked to recommendations.Business rules satisfied.Claims with unresolved compliance issues should be flagged before submission.15. NotificationsUsers may be notified when:A claim is assigned.Required documents are missing.AI analysis completes.Compliance review identifies issues.Carrier responses are recorded.Notification preferences should be configurable per user in future versions.16. ReportingThe module should provide metrics such as:Total active claims.Claims by status.Average processing time.Supplements submitted.Revenue recovered.Approval rates.Outstanding tasks.These metrics feed the dashboard and management reports.17. Business RulesExamples include:A claim cannot enter AI Analysis without the minimum required documentation.A supplement cannot be submitted until compliance validation passes or an authorized user records an override.Every status change must be logged.Deleting a claim should be restricted and auditable; archiving is preferred.18. Acceptance CriteriaThe Claims Management module is complete when users can:Create and manage claims.Assign responsibility.Track claim status.Upload and organize related evidence.Record notes and tasks.Trigger AI analysis.Generate supplements.Complete compliance reviews.Review the full activity timeline.Produce management reports based on claim data.Documentation ProgressCompleted specifications:✅ System Architecture✅ Repository Structure & Development Environment✅ Database Architecture & Data Model✅ Authentication & Authorization✅ API Architecture & Service Layer✅ Frontend Architecture & Design System✅ Claims Management ModuleNext Document: Document Management & Intelligence ModuleThis specification will define how Atlas handles document ingestion, storage, OCR processing, metadata extraction, classification, versioning, search, AI analysis, and evidence linking.
